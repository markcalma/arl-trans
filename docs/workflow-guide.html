ARL-Trans — Workflow Guide

Who's involved, what happens, what it replaces, and what comes out — for all 3 workflows.

WF1
Turns Gary's weekly manual spreadsheet work into a daily automatic process so containers never miss their deadline
WF2
Turns Lorene's manual dispatch process into an automatic one the moment a delivery order arrives
WF3
Automatically matches carrier invoices to load records and flags anything that doesn't add up before AP ever sees it

WF1 — Water Report

Daily Container Tracking

Replaces Gary's manual daily reconciliation of the water report, Load Board updates, and carrier emails.

⚡ Trigger — Water report email arrives in orders@arl-trans.com
Who is involved
Amercare
Sends daily water report Excel file
Mikki Corvey
Sends daily work order schedule (Track 2)
Gary
Owns Master Container List — WF1 replaces his daily work
Carriers
Read the Load Board to know what to pick up
What happens step by step
1
Amercare sends the water report — a daily Excel file listing all their active containers, where they're going, and when they arrive at port.
2
WF1 parses the file — reads every container row and extracts container number, ETA, destination, steamship line, and free days.
3
Master Container List updated — new containers added, existing containers updated with new ETAs. Exam-flagged rows are never touched.
4
LFD scraped from port websites — Last Free Day is the deadline before the port charges $400/day. WF1 checks the terminal website to get the exact date. If the water report already has it, that value is used instead.
5
Per diem date calculated — how many free days the steamship line allows + the unloaded date = when charges start if the container hasn't been picked up.
6
Load Board updated — each container is sorted into the right tab (Stockton, Exton, Carsen, etc.) so carriers can see their assigned pickups.
7
Two emails sent automatically — one to Amercare (container status, no pricing), one to carriers (pickup list with container numbers, ETAs, and deadlines).
Gary does this manually today
  • Opens water report every 2–3 weeks
  • Copy-pastes into spreadsheet by hand
  • Checks multiple port websites for LFD
  • Calculates per diem dates manually
  • Sorts containers into Load Board tabs
  • Writes and sends carrier emails
  • Writes and sends Amercare emails
WF1 does this automatically
  • Runs every day the moment email arrives
  • Parses Excel and writes to Google Sheets
  • Scrapes port websites for LFD
  • Calculates per diem from free days key
  • Routes containers to correct tab
  • Generates and sends carrier email
  • Generates and sends Amercare email (no pricing)
Final outputs
What comes out
1
Master Container List updated — all containers current with LFD and per diem dates filled in
2
Amicare Load Board updated — every tab sorted by ETA, carriers see current data
3
Email to Amercare — container status update, no carrier pricing
4
Email to carriers — pickup list in Gary's format (container number, ETA, pickup date, termination date)
Important rules
🚫 Never overwrite exam-flagged rows — Gary marks these manually when customs puts a container on hold
🔁 Duplicate container numbers are valid — same container used twice (reuse load) must be flagged, not deleted
💰 Carrier pricing must never appear in the Amercare email — two completely separate emails, always
📊 Column D blank = use Column P + port rules as fallback for free days calculation

WF2 — Order Intake

Delivery Order Processing & Dispatch

Replaces Lorene's manual process of reading delivery orders, creating Truckman loads, and dispatching carriers.

⚡ Trigger — Delivery order email arrives in orders@arl-trans.com
Who is involved
Amercare / Taggart / OOCL
Send the delivery order by email
ARL-Trans (Lorene)
Receives DO and arranges trucking — WF2 replaces her
Carrier
Gets hired and dispatched to pick up the container
What happens step by step
1
Delivery order arrives by email — sent by Amercare, Taggart International, or OOCL. It means "this container is at the port, go pick it up and deliver it here."
2
WF2 reads the email and any attachments — parses the email body for container number, MBL, customer ref, and destination. If there's a PDF, AI extracts the same fields from it. Both are merged.
3
Dedup check — is this container already in the Master Container List from the water report? If yes, skip writing it. If no, add it now. (This is what Gary was doing manually when he said "I don't see this one.")
4
Truckman load record created — WF2 creates the load in Truckman (ARL-Trans' TMS) with the container number, destination, and customer details already filled in.
5
Carrier rate looked up automatically — WF2 checks the rate sheet to find what ARL-Trans agreed to pay the carrier for this route. No manual typing. This is where Lorene's billing errors happen today.
6
Carrier assigned and dispatched — WF2 finds the correct carrier using their MC number, then sends them two things at once: the rate confirmation (how much they'll be paid) and the dispatch (container details, pickup location, delivery address).
Lorene does this manually today
  • Reads every DO email
  • Opens Truckman and creates load by hand
  • Looks up carrier rate on a spreadsheet
  • Types rate into Truckman manually
  • Sends rate confirmation to carrier
  • Sends separate dispatch to carrier
  • Wrong rate entries = billing errors
WF2 does this automatically
  • Detects DO email the moment it arrives
  • AI reads email body and PDF attachments
  • Creates Truckman load automatically
  • Pulls rate from rate sheet — no typing
  • Sends rate confirmation + dispatch together
  • Flags non-standard lanes for human review
  • Zero manual rate entry = zero rate errors
Final outputs
What comes out per delivery order
1
Master Container List updated — container added if it wasn't already there from WF1
2
Truckman load record created — with correct container, destination, customer, and carrier rate
3
Carrier dispatched — one email with both the rate confirmation and dispatch instructions sent automatically
Important rules
📄 DO emails come from multiple senders — Amercare (weareacr.com), Taggart (taggart-intl.com), OOCL. WF2 must catch all of them
🤖 PDF formats vary — Taggart DO, OOCL customs DO, packing list. AI parser must handle all formats
⚠️ Non-standard lane = human exception. If no rate found in the rate sheet, flag to the ops team and stop
🔗 Truckman integration path is TBD — API, browser automation (Playwright), or hybrid. Confirmed after Greg provides dev docs

WF3 — Carrier Invoice Portal

Invoice Matching & Load Close-Out

Automates the matching of carrier invoices to Truckman load records and flags discrepancies before the AP team sees them.

⚡ Trigger — Carrier invoice email arrives in AP inbox
Who is involved
Carrier
Emails invoice after delivery to get paid
ARL-Trans AP Team
Processes payments — WF3 only sends them clean invoices
Truckman
Contains every load record with the agreed rate
What happens step by step
1
Carrier delivers the container — job done. Now they want to get paid. They email their invoice to ARL-Trans.
2
AI classifies the document — not every email attachment is an invoice. It could be a POD (proof of delivery), a TIR ticket, or something else. AI reads it and identifies exactly what it is before doing anything.
3
Container number extracted — AI pulls the container number from the invoice. This is the key used to find the matching load in Truckman and the Master Container List.
4
Rate check — WF3 compares the invoiced amount against the agreed rate in the rate sheet. Does the carrier charge match what was agreed when WF2 dispatched them?
5A
If rate matches — invoice attached to Truckman load record, load flagged for close-out, Master Container List Col X updated to "Invoiced", AP team notified it's ready to pay.
5B
If rate doesn't match — AP team gets a discrepancy alert showing expected vs actual amount. Carrier gets an email explaining the mismatch. A human resolves it before any payment is made.
AP team does this manually today
  • Opens every invoice email one by one
  • Reads container number from invoice
  • Searches Truckman for matching load
  • Checks rate against rate sheet manually
  • Closes load if rate matches
  • Emails carrier to dispute if it doesn't
  • Invoices pile up and loads stay open
WF3 does this automatically
  • Monitors inbox continuously
  • AI classifies every attachment
  • Extracts container number automatically
  • Checks rate against rate sheet
  • Closes clean loads without human input
  • Flags only the problem invoices
  • AP team only touches what needs attention
Final outputs
What comes out per invoice
✓
Rate matches → Invoice attached to Truckman load + load flagged for close-out + Master List Col X = "Invoiced" + AP team notified
✗
Rate doesn't match → AP team gets discrepancy alert + carrier gets email explaining the mismatch + load stays open until resolved
Important rules
🤖 AI classification is required — attachments can be invoices, PODs, TIR-in, TIR-out, or other. WF3 must know the difference before acting
🔗 WF3 cannot start until WF2 is live — it depends on clean Truckman load records that WF2 creates. No WF2 = no load records to match against
📎 One email can have multiple attachments — WF3 loops through each one separately and handles them individually
💳 Never auto-pay — WF3 only flags loads as ready for close-out. A human in AP always makes the final payment decision
